# Задача 2. Недельная и месячная сводки в Power Query

## Как запустить в Excel

1. Откройте готовую книгу анализа в Excel с Power Query. В неё встроены `pCsvPath`, `SalesModel`, `Weekly` и `Monthly`. На листе **Динамика** сохранены месячная и недельная таблицы с проверенными результатами.
2. Откройте **Данные → Запросы и подключения → pCsvPath**. В редакторе параметра укажите полный путь к `sales_data.csv`. В Excel 2016 панель может называться **Показать запросы**. В книге сохранён путь к исходнику, использованному при расчёте.
3. Закройте редактор и выберите **Данные → Обновить всё**. `Weekly` и `Monthly` связаны с двумя таблицами листа **Динамика**. Для обеих задана последовательная загрузка с сохранением ширины колонок и форматов. При изменении числа строк таблица вставляет или удаляет ячейки.

Файлы `.pq` содержат исходный код тех же запросов. В шаблоне `pCsvPath.pq` указан переносимый пример `C:\Data\sales_data.csv`. Для переноса в другую книгу создайте четыре пустых запроса с указанными именами, вставьте соответствующий код через расширенный редактор, а результаты `Weekly` и `Monthly` загрузите на листы. Заголовки выходных колонок на русском совпадают с готовой книгой.

[Инструкция Microsoft по созданию и загрузке запросов в Excel](https://support.microsoft.com/ru-ru/excel/create-load-or-edit-a-query-in-excel-power-query)

## Правила расчёта

- `SalesModel` содержит подготовленные строки `Sales` и две сводки `Weekly` и `Monthly`. Исходник читается в UTF-8, разделитель полей — запятая, десятичный разделитель — точка. Идентификаторы хранятся как текст.
- Из 40 020 строк удалены 20 точных повторов и 100 строк без цены закупки. В оставшихся 39 900 строках 50 отрицательных значений `quantity_sold` заменены нулём. Нулевая продажа сохраняет закупки и потери строки. Все три поля количества приводятся к целым числам, отрицательные значения обнуляются, а пустые и дробные вызывают ошибку.
- `YearMonth` строится по дате операции. `WeekStartDate` — понедельник. ISO-год для `YearWeek` определяется по четвергу той же недели. Неделя с 4 января получает номер `01`.
- `Gross Margin %` = валовая прибыль / выручка. Закупочная стоимость проданных единиц берётся из строк продаж. `Losses %` = стоимость потерь / стоимость закупки. `Avg Selling Price` = выручка / количество проданных единиц. При нулевом знаменателе показатель остаётся пустым.
- `Turnover` = 7 × сумма продаж в штуках / (сумма закупок в штуках + сумма потерь в штуках). Коэффициент 7 применяется в обеих сводках по условию задания.
- `Avg Weekly Turnover` — простое среднее рассчитанных недельных `Turnover` по месяцу понедельника. Неделя учитывается в одном месяце. Неделя `2023-39` начинается 25 сентября и содержит только операции за 1 октября. В `Weekly` она представлена отдельной строкой, а при расчёте среднего относится к сентябрю. Операции 1 октября входят в октябрьские итоги `Monthly` по дате операции.

## Сверка на данных задания

Все четыре M-запроса прошли синтаксический разбор в `Microsoft.MashupEngine.dll` установленного Excel 2016. `SalesModel`, `Weekly` и `Monthly` выполнены в этом движке на исходном `sales_data.csv` с подстановкой фактического пути в параметр `pCsvPath`.

Результаты сверены с независимым расчётом на Python. Совпали число подготовленных строк — 39 900, все ключи 14 недель и 3 месяцев, а также 88 числовых ячеек сводок. Все значения выручки совпали точно, наибольшее абсолютное расхождение остальных показателей составило `5 × 10⁻¹⁴` при допуске `10⁻¹⁰`. Сумма выручки каждой сводки равна **6 770 833 903,39 ₽**.

Готовый XLSX содержит нативный контейнер `DataMashup` формата Microsoft MS-QDEFF, четыре запроса M, два подключения и две связанные таблицы с сохранёнными данными. Нативная библиотека Microsoft прочитала контейнер, метаданные, конфигурацию и встроенный `Section1.m`. Встроенный код прошёл разбор M. Проверка полного XLSX через Microsoft Open XML SDK завершилась с нулём ошибок. Даты понедельников хранятся как серийные даты Excel с форматом `yyyy-mm-dd`.

Команда обновления непосредственно в интерфейсе Excel остаётся непроверенной из-за ошибки запуска Excel через COM `0x80080005`. Числовые результаты рассчитаны движком Microsoft Power Query и сохранены в книге.
